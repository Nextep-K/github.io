# Pre-fix Baseline — 웹검색·맥락 지속성 수정 전 대화

작성일: 2026-10-04  
용도: 회귀 테스트 기준선

> **보존 목적** — 웹검색 자동화 및 Traveler/Observer 분리 수정 직전의 실제 대화 결과를 회귀 테스트 기준선으로 저장한다.

## 환경
- 앱: Context Tourism Pilot · Streamlit v0.3
- 상태: OpenAI 연결됨 / Notion 연결됨 / 브라우저 위치 연결됨
- Journey: `MOVING`
- 목적지: 월정사
- 교통수단: 자가용
- 당시 구조: Traveler 응답과 Event 관찰을 한 번의 구조화 출력 호출에 결합
- 당시 웹검색 도구: 미연결

## 실제 대화 — 수정 전

**Assistant**
여행을 시작해 보겠습니다. 지금 어디에 있고, 어디로 가실 예정인가요?

**User**
오늘 진조리에서 월정사에 자가용으로 갈 거야.

**Assistant**
좋아요. 오늘 진조리에서 월정사까지 자가용으로 이동하실 계획이군요. 출발 시간이나 경로도 함께 살펴볼까요?

**User**
지금 출발

**Assistant**
출발하셨군요. 월정사까지 안전하게 이동하세요.

**User**
가는 중에 추천할 식당과 주차장 정보 알려줘

**Assistant**
운전 중이라면 휴대폰은 조작하지 말고, 안전한 곳에 정차한 뒤 확인해 주세요. 월정사 방문객 주차장과 식당은 월정사 인근 및 진부면 쪽을 우선 살펴보시면 좋습니다. 실시간 운영 여부나 현재 경로에 맞는 식당을 정확히 안내하려면 내비게이션 경로(예: 어느 고속도로 이용 중인지)와 식사 선호를 알려주세요.

**User**
지금은 정차 중 - 너가 검색해서 추천해 줘

**Assistant**
실시간 웹 검색은 할 수 없어 영업 여부나 주차 요금은 확인해 드릴 수 없습니다. 일반적으로는 월정사 입구 상가의 산채정식·막국수 식당을 먼저 살펴보시고, 식당 선택지가 더 필요하면 진부면 소재지 쪽을 확인해 보세요. 주차는 월정사 방문객 주차장을 이용하는 것이 가장 편리합니다. 도착 전 운영 시간과 요금은 지도 앱이나 현장 안내판으로 확인해 주세요. 정차 중이시더라도 운전 재개 전에는 휴대폰을 조작하지 마세요.

## 관리자 화면에 생성된 주요 Event
- `Intent / 여행 계획` — 진조리에서 월정사로 갈 예정
- `Choice / 교통수단 선택` — 자가용
- `Movement / 출발` — 진조리 → 월정사 이동 시작
- `Intent / recommendation` — 이동 중 식당·주차장 정보 요청
- `Exposure / general_travel` — 월정사 방문객 주차장·진부면 일대 식당에 대한 일반적 안내

## 확인된 문제
1. **대화 맥락 지속성이 약함** — 이미 목적지·교통수단·이동 상태가 정해졌는데도 응답이 현재 Journey를 충분히 활용하지 못했다.
2. **검색 부재** — 사용자가 명시적으로 검색을 요구했는데도 웹검색을 수행하지 못했다.
3. **구체성 부족** — 실제 식당명, 운영 여부, 주차 요금·위치 등 의사결정에 필요한 구체 정보가 없었다.
4. **불필요한 안전문구 반복** — 사용자가 정차 중이라고 밝혔는데도 운전 안전 경고를 반복했다.
5. **과도한 되묻기** — 먼저 가능한 답을 제공하기보다 경로·식사 선호를 다시 요구했다.
6. **Traveler와 Observer 결합 문제** — 사용자에게 유용한 답변 생성과 Event 구조화를 한 호출에 묶어 응답 품질이 데이터 수집 쪽으로 평평해졌다.
7. **Exposure 판정 문제 가능성** — 실제로 구체적 외부 정보를 제시하지 않았는데도 일반 안내가 Exposure로 기록되었다.

## 이 기준선으로 이후 비교할 것
- 동일 질문에서 웹검색이 실제 실행되는가
- 이전 대화·Journey 상태를 이어서 답하는가
- 실제 장소명과 근거 있는 주차·식당 정보를 제시하는가
- 사용자가 이미 말한 정보를 다시 묻지 않는가
- 안전문구를 상황에 맞게 최소화하는가
- Traveler 답변과 Observer Event가 서로 독립적으로 품질을 유지하는가
